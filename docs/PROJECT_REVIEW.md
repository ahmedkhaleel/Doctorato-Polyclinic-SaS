## 2) المعمارية (Architecture)

- **Stack:** Laravel 12 (PHP 8.3) + Vue 3 + Inertia v2 + Tailwind 4 (Vite).
  MySQL إنتاج، SQLite في CI. استضافة cPanel مشتركة (الجذر = `public_html`).
- **خمس لوحات** منفصلة (Layout + middleware لكل منها):
  | اللوحة | المسار | الحماية |
  |--------|--------|---------|
  | الواجهة العامة | `/` | web |
  | المريض | `{locale}/patient/…` | patient.auth |
  | الطبيب | `/doctor/…` | doctor.auth |
  | السكرتير | `/secretary/…` | secretary.auth |
  | الأدمن | `/admin/…` | admin.auth |
  | الويبماستر | `/webmaster/…` | webmaster.auth |
- **أنظمة مفتاحية:**
  - `ModuleManager` — مفاتيح ميزات لكل وحدة (derma, dental, pediatric, obgyn,
    telemedicine, hr, inventory, insurance).
  - `Setting` — مفتاح/قيمة لكل شيء قابل للضبط (مع تشفير للمفاتيح الحسّاسة + تجاوز
    لكل فرع).
  - **تعدد الفروع** — `BranchContext` + `BelongsToBranch`/`StampsBranch` على 76
    نموذجاً، خلف kill-switch (`BRANCHES_ENABLED`).
  - **الإشعارات الموحّدة** — `Notifier`/`NotificationService` + قنوات
    (email/SMS/WhatsApp/in-app) + توجيه الأحداث + قوالب + موافقات + ساعات هدوء +
    سقف تكرار + حملات + سلاسل تنقيط + A/B + DLR.
  - **الدفع** — `PaymentGatewayManager` + Paymob/Stripe.

## 3) سير العمل الأساسي (Core Workflows)

### 3.1 رحلة المريض والحجز (العمود الفقري)
```
زائر/Lead → حجز (موقع عام أو سكرتير أو بوابة المريض، باختيار فرع)
          → تأكيد → إنشاء/ربط مريض (file_number تلقائي)
          → زيارة (Visit) ← مواعيد (BookingAppointment)
          → خدمات/علاج تخصصي → فاتورة (Invoice) + بنود
          → دفعات (Payment) → عمولات الطبيب/المسوّق
          → إشعارات (تأكيد/تذكير) → متابعة/استدعاء/رضا
```
- الترقيم لكل فرع: `BK / INV / CN / MC / PB / TELE / PAY / CLM / SAL` —
  الفرع الرئيسي يحتفظ بالصيغة القديمة، الفروع الأخرى تحمل كود الفرع (لا تصادم).
- المواعيد المتاحة تُولَّد من جداول الأطباء (`OnlineSlotGenerator`/`TimeSlotService`)
  وتحترم الفرع المختار.

### 3.2 CRM
```
Lead (مصدر/حملة) → تسجيل/إسناد آلي (قواعد) → أنشطة/متابعات → تأهيل/تنقيط
     → تحويل (convert) → مريض + حجز اختياري (كل الأقسام بما فيها OB/GYN)
```
- مركزي مشترك عبر الفروع (`branch_id` للإسناد/التقارير فقط).

### 3.3 العيادات التخصصية (Event-based، معزولة بالفرع)
- **الأسنان:** مخطط الأسنان، خطط علاج، علاجات، أشعة، طلبات معمل، متابعات، مقارنات.
- **الجلدية والتجميل:** جلسات، خطط، إجراءات تجميل، باقات، موافقات، معرض قبل/بعد.
- **الأطفال:** زيارات الطفل السليم، تطعيمات (+بطاقة)، نمو (+تقرير)، فحوصات، تغذية.
- **النساء والتوليد:** ملفات الحمل، زيارات المتابعة، سونار، تحاليل، مسحات، ولادات.
- سجلّات الحالة الدائمة للمريض (حساسيات/مزمنة) **مشتركة** (تتبع المريض المشترك).

### 3.4 المالية
الفواتير، الدفعات، إشعارات الدائن، الخصومات، المحافظ، طرق الدفع، عمولات الأطباء
(payout/salary)، عمولات المسوّقين، المصروفات. التقارير: مالي، تحليل إيرادات، KPIs،
ومقارنة بين الفروع. **الصلاحية المالية منفصلة** (`reports.financial`).

### 3.5 الموارد البشرية
الموظفون، الورديات، الحضور، الإجازات (طلب/اعتماد)، قسائم الرواتب، السلف،
الجزاءات، جداول الأطباء، صرفيات الأطباء.

### 3.6 المخزون والتأمين
- مخزون لكل فرع (المخزون/الحركات/أوامر الشراء)، موردون مشتركون، إعادة طلب تلقائي
  عند انخفاض المخزون (per-branch). `sku/barcode` فريد لكل فرع.
- التأمين: شركات، خطط، تأمينات المرضى، مطالبات، موافقات مسبقة، تقارير.

### 3.7 الإشعارات (تاب موحّد)
المركز (تفعيل القنوات + ربط الأحداث بالقنوات + القوالب + الإعدادات + اختبار)
· الحملات · سلاسل التنقيط · **المجدولة** · سجل الإرسال · التحليلات · الوارد ·
قوالب واتساب/SMS · التنبيهات. مُرسِل مركزي واحد للمنظّمة (قرار مُثبّت)، والسجلّ
يُنسب لفرع المعاملة للتحليلات.

### 3.8 التطبيب عن بُعد
استشارات أونلاين (Agora) — حجز/دفع/غرفة فيديو، مع لوحة جاهزية (5 معوّقات) في
`/health` و`/admin/settings/telemedicine`.

### 3.9 تعدّد الفروع (مبني، خلف مفتاح)
عزل بيانات كامل (Global Scope) + سياق per-request + الكونسول يعالج كل الفروع +
ترقيم/إعدادات لكل فرع + مبدّل في كل اللوحات + إسناد الموظفين/الأطباء + تقارير
مقارنة + فحوص سلامة + ترويسات PDF لكل فرع + عزل تلقائي عند ربط النماذج بالمسار.
`BRANCHES_ENABLED=false` افتراضياً ← الإنتاج يعمل كعيادة واحدة بلا تغيير.

## 4) الصلاحيات والأمان
- كتالوج مركزي واحد (`config/permissions.php`، 297 صلاحية) → صفحة الأدوار.
- 9 أدوار مبذورة (super_admin بـ `*`، مدير، محاسب، طبيب، سكرتير، استقبال…).
- تحكّم دقيق لكل ميزة جديدة (الفروع/الولاء/الاستدعاء/التطبيب/التأمين/HR) بنمط OR
  غير كاسر + التقارير المالية منفصلة.
- اختبار `PermissionsCatalogTest` يضمن أن كل صلاحية يفحصها الكود موجودة بالكتالوج.
- عزل اللوحات (whitelist بالأدوار)، حماية الطبقة الحسّاسة الطبية (`view_sensitive_medical`)
  وسجلّ وصول طبي (HIPAA-style)، عزل الفروع التلقائي عبر route-model binding.

## 7) ما أُنجز مؤخراً (هذه الدورة)
1. **تعدّد الفروع الكامل** (B0→H + 7 فجوات) + إصلاح عزل route-model binding.
2. **إصلاحات إنتاج:** أمان الـ traits قبل migration، وتوصيل OB/GYN بالكامل
   (booking_type → VARCHAR) لحل خطأ 500.
3. **اتساق اللوحات الخمس:** سايدبار مكتمل + وصول سريع + مؤشرات تشغيلية بالأدمن.
4. **توحيد الصلاحيات:** سدّ كل الفجوات + صلاحيات دقيقة جديدة + فصل التقارير المالية.
5. **تاب الإشعارات الموحّد** + بناء صفحة "المجدولة" الناقصة.
6. **وثائق:** ADR + checklist + سيناريو staging + هذا التقرير.

## 9) الحالة النهائية
نظام **متكامل ومتّسق وجاهز للإنتاج** كعيادة واحدة الآن، و**جاهز لتفعيل تعدّد الفروع**

الخمس، ومحميّة باختبارات + حُرّاس (catalog guard، cross-branch، cron all-branches).
