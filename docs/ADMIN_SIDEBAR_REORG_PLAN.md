# Admin Sidebar Reorganization
## خطة إعادة تنظيم القائمة الجانبية (أدمن / سوبر أدمن)

**Date:** 2026-06-07 · **Type:** IA + frontend + ux-copy plan (خطة قبل التنفيذ)
**Component:** `resources/js/Layouts/AdminLayout.vue`

> الهدف: **إعادة ترتيب وتنسيق** القائمة الجانبية إلى تسلسل هرمي احترافي (محاور رئيسية →
> أقسام → عناصر) بأنيميشن منسّق ومتناسق على الويب والموبايل — **دون حذف أو فقد أي صفحة**،
> فقط إعادة تجميع/تنسيق. مع **أداة تحقّق آلية** تضمن عدم كسر أو فقد أي رابط.

---

## 1) الوضع الحالي (مبني على الكود)

- قائمة واحدة في `AdminLayout.vue` (1102 سطرًا): **19 مجموعة، 192 رابطًا فريدًا**.
- مجموعات قابلة للطيّ (`openGroups` + `toggleGroup`)، أنيميشن طيّ (`.nav-collapse`)،
  بوّابات لكل عنصر (`permission` + `moduleKey`)، درج **overlay على كل المقاسات** (RTL-aware،
  يُغلق عند النقر، يُحفظ في localStorage).
- **المشكلات:**
  1. **19 محورًا مسطّحًا** = تمرير طويل، صعوبة المسح البصري.
  2. **مجموعات متضخّمة بمستوى واحد**: System **25**، Derma **18**، CRM **14**, Dental **13**, Website **12**, Notifications/Neurology/HR/Clinic **11**.
  3. **6 مجموعات تخصصات منفصلة** (أسنان/أطفال/نساء/نفسي/أعصاب/جلدية) تظهر معًا في عيادة متعدّدة التخصصات → فوضى.
  4. لا «فتح تلقائي» للمحور/القسم الذي يحتوي الصفحة الحالية (active trail).

---

## 2) البنية المقترحة — هرم من 3 مستويات (محور → قسم → عنصر)

تُطوى الـ19 مجموعة إلى **~8 محاور (pillars)**، كلٌّ يحوي المجموعات الحالية **كأقسام فرعية**.
**كل الـ192 رابطًا يبقى — فقط يُعاد تعشيشه.** (الأقسام الفرعية تظهر فقط لو وحدتها مفعّلة/صلاحيتها متاحة.)

| المحور (Pillar) | يضم (الأقسام الحالية) | لماذا |
|---|---|---|
| **لوحة القيادة** Overview | Main | نقطة البداية، مسطّح بلا أقسام |
| **العيادة** Clinic | Clinic | التشغيل اليومي (مرضى/زيارات/أطباء/وصفات…) |
| **التخصصات** Specialties | Dental · Pediatrics · OB/GYN · Psychiatry · Neurology · Dermatology | **6 محاور → محور واحد بـ6 أقسام** (أكبر مكسب) |
| **المالية** Finance | Finance · Insurance | كل ما يخص المال |
| **النمو** Growth | CRM · Telemedicine | الاكتساب والإيراد |
| **المخزون** Inventory | Inventory | كما هو |
| **الفريق** People | HR | الموارد البشرية |
| **التفاعل** Engagement | Notifications · Quality & Engagement · AI | تواصل المرضى والذكاء |
| **النظام** System | System · Website | الإعدادات والموقع — **يُقسَّم System (25) داخليًا** إلى أقسام فرعية: الإعدادات · المستخدمون والأدوار · السجلّات والتدقيق · التكاملات · البيانات |

> النتيجة: من **19 عنصرًا مسطّحًا** إلى **~8 محاور** قابلة للطيّ، كلٌّ بأقسامه — تمرير أقصر،
> مسح أسرع، وتجميع منطقي. لا رابط يُحذف.

## 3) المصدر الموحّد + التعشيش (architecture)

- **استخراج تعريف القائمة** من `AdminLayout.vue` إلى وحدة واحدة
  `resources/js/Layouts/adminNav.js` (مصدر حقيقة واحد) — يُسهّل الصيانة والتحقّق.
- بنية البيانات الجديدة (3 مستويات، متوافقة-للخلف — قسم بلا `sections` = سلوك المستوى الحالي):
  ```js
  { key, titleAr, titleEn, icon, moduleKey?, sections: [
      { key, titleAr, titleEn, moduleKey?, items: [ { …كما هي، href/permission/moduleKey } ] }
  ] }
  ```
- منطق العرض: محور قابل للطيّ → قسم قابل للطيّ → عناصر. تُعاد كتابة `openGroups`
  لتدعم مفاتيح متداخلة (`pillar` و`pillar.section`).
- **بوّابات كما هي**: تظهر العناصر/الأقسام/المحاور فقط لو لها عنصر واحد مرئي على الأقل
  (نفس فلترة `permission`/`moduleKey` الحالية، تُطبّق تصاعديًا).

## 4) التفاعل والأنيميشن (frontend)

- **Active trail تلقائي:** عند التحميل يُفتح المحور + القسم الحاوي للمسار الحالي، ويُبرز العنصر النشط (ومساره).
- **أكورديون متداخل:** طيّ/فتح بارتفاع متحرّك (موجود `.nav-collapse`) للمحور والقسم.
- **ظهور متدرّج** للعناصر عند فتح القسم (`animation-delay` تتابعي).
- **دوران chevron**، وميض ذهبي على رأس المحور (موجود)، ومؤشّر نشط بخطّ ذهبي جانبي.
- **«طيّ الكل / فتح الكل»** + تذكّر حالة الطيّ في localStorage (مفتاح جديد `v3`).
- **احترام `prefers-reduced-motion`** (ظهور فوري).
- **تناسق ويب/موبايل:** نفس المكوّن؛ على الموبايل يبقى درج overlay (موجود) — نفس الهرم، مساحات لمس أكبر (44px)، يُغلق عند الاختيار.

## 5) UX copy (ux-copy)
- أسماء المحاور ثنائية اللغة (أعلاه)، قصيرة (كلمة واحدة) واضحة.
- رؤوس الأقسام = أسماء المجموعات الحالية (مألوفة، لا إرباك).
- عناصر تبقى بنصوصها الحالية حرفيًا (لا تغيير label).

## 6) أداة التحقّق «لم يُكسر شيء» (الأهم) 🔒

ثلاث طبقات آلية:

### 6.1 جرد الروابط الأساسي (baseline) — قبل أي تعديل
```bash
grep -oE "href: '[^']+'" resources/js/Layouts/AdminLayout.vue \
  | sed "s/href: '//;s/'//" | sort -u > tests/fixtures/admin_sidebar_hrefs.txt   # 192 سطرًا
```

### 6.2 اختبار حارس `AdminSidebarIntegrityTest` (PHPUnit) — يُشغَّل قبل/بعد
1. **لا فقدان رابط:** يستخرج كل `href` من `adminNav.js` (أو `AdminLayout.vue`) ويؤكّد أنه
   **مجموعة عُليا ⊇ الأساس** (192) — أي رابط مفقود = فشل، مع طباعة الفروقات.
2. **كل رابط يُحلّ لمسار مُسجَّل:** لكل href (بعد تجريد الاستعلام) يؤكّد وجود route مطابق
   (عبر `Route::getRoutes()` بمطابقة URI) — يلتقط أي خطأ مطبعي/رابط مكسور من إعادة الترتيب.
3. **(اختياري) دخان حيّ:** كسوبر أدمن، GET لعيّنة من الروابط الثابتة (بلا بارامترات) وتأكيد ≠ 404/500.

### 6.3 شبكات الأمان القائمة (تبقى خضراء)
- `composer test` كامل (1560+ اختبارًا) + حُرّاس الواجهة (Emoji/IconLabel/ImageAlt/FocusTrap).
- فحص سلامة الـ manifest في CI (لا صفحة Inertia مفقودة).
- CI + Deploy + `/health` بعد النشر.

> ضمان عدم الكسر = **(الأساس 192) ⊆ (الجديد) + كل رابط يُحلّ + كل الاختبارات خضراء**.
