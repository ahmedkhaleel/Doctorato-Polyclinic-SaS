# خطة دمج الذكاء الاصطناعي — Doctorato Polyclinic

> **ADR / System Design** — كيف نستفيد من OpenAI في النظام بالكامل، بشكل منسّق،
> مع تحكّم كامل من لوحة تحكم الأدمن. **هذه خطة قبل التنفيذ — لا كود بعد.**
>
> الحالة: **مقترحة (Proposed)** · التاريخ: 2026-06-01 · النطاق: كل اللوحات (أدمن/طبيب/سكرتير/مريض/الموقع)

---

## 1. الرؤية والمبادئ

نُدخل طبقة ذكاء اصطناعي **مركزية وقابلة للتبديل** (OpenAI الآن، وغيره لاحقًا) تخدم كل
وحدات النظام، مع الالتزام بـ:

1. **التحكم الكامل من لوحة الأدمن** — لا مفاتيح ولا نماذج ولا ميزات مكتوبة في الكود؛ كلها
   من `Settings`. مفتاح OpenAI **مُشفّر**.
2. **مفتاح إيقاف عام (Kill-switch)** — `ai_enabled=false` يوقف كل شيء فورًا دون كسر النظام
   (كل ميزة لها بديل "بدون AI").
3. **الإنسان في الحلقة دائمًا للقرارات الطبية** — الـ AI يقترح، الطبيب يعتمد. لا تشخيص
   تلقائي ولا وصفة تُرسل بلا موافقة بشرية.
4. **خصوصية البيانات الطبية** — تقليل/إخفاء المعرّفات الشخصية (PHI) قبل الإرسال، موافقة
   المريض، سجل تدقيق لكل طلب.
5. **ضبط التكلفة** — سقف شهري للإنفاق، قاطع دائرة (circuit breaker)، تدرّج النماذج
   (الرخيص للمهام البسيطة، القوي للطبية)، تخزين مؤقت.
6. **متعدد اللغات** — كل مخرجات الـ AI عربي/إنجليزي حسب لغة المستخدم.
7. **فرع-واعٍ (Branch-aware)** — كل طلب AI يُختم بـ `branch_id`، وميزانية لكل فرع اختياريًا.

## 2. المعمارية عالية المستوى

نحاكي نمط `Payment/` الموجود (Manager + Drivers) لأنه مُجرَّب في المشروع:

```
app/Services/Ai/
  AiManager.php              ← يقرأ الإعدادات، يختار الـ driver، يطبّق الحُرّاس
  Contracts/AiDriver.php     ← واجهة: chat(), vision(), embed(), transcribe(), moderate()
  Drivers/
    OpenAiDriver.php         ← تنفيذ OpenAI (chat/vision/whisper/embeddings)
    NullDriver.php           ← بديل آمن عند تعطيل الـ AI (يرجع رسالة "غير مفعّل")
    (مستقبلًا) AnthropicDriver, AzureOpenAiDriver
  AiGate.php                 ← بوابة الحُرّاس: feature flag + budget + rate limit + PHI redaction
  AiCostMeter.php            ← حساب التوكنز/التكلفة وتسجيلها
  PhiRedactor.php            ← إخفاء الأسماء/الهواتف/الأرقام القومية قبل الإرسال
  Features/                  ← منطق كل ميزة (سطر رفيع فوق AiManager)
    ClinicalNoteWriter.php
    PrescriptionSuggester.php
    PatientAssistant.php     (Chatbot/RAG)
    CommsDrafter.php
    SeoContentWriter.php
    LeadReplyDrafter.php
    InsightAnalyst.php       (تحليلات بلغة طبيعية)
    ...
```

**تدفّق الطلب:**

```
Controller/Job → Feature class → AiGate (هل الميزة مفعّلة؟ هل ضمن الميزانية؟
   redact PHI) → AiManager → OpenAiDriver → OpenAI API
                                   ↓
                          AiCostMeter يسجّل في ai_request_logs (تكلفة/توكنز/زمن/فرع/مستخدم)
```

**مبادئ تقنية:**
- كل المهام الثقيلة عبر **Queue** (لا تُبطئ الطلب)، مع streaming للمحادثة.
- **تخزين مؤقت** للنتائج القابلة لإعادة الاستخدام (embeddings، ترجمات، أوصاف خدمات).
- **محاولة + تراجع آمن**: عند فشل/تعطّل OpenAI → `NullDriver` أو رسالة واضحة، لا 500.

## 3. التحكّم من لوحة الأدمن (Settings)

### 3.1 مفاتيح الإعدادات (في جدول `settings`، group=`ai`)

| المفتاح | النوع | الوصف |
|---|---|---|
| `ai_enabled` | boolean | المفتاح العام (Kill-switch) |
| `ai_provider` | select | `openai` (افتراضي) / مستقبلًا غيره |
| `ai_openai_api_key` | **مشفّر** | مفتاح OpenAI (يُضاف لـ `Setting::isEncryptedKey()`) |
| `ai_openai_org` | text | المؤسسة (اختياري) |
| `ai_default_model` | select | `gpt-4o-mini` افتراضيًا |
| `ai_clinical_model` | select | نموذج المهام الطبية (`gpt-4o`) |
| `ai_vision_model` | select | `gpt-4o` للصور |
| `ai_embedding_model` | select | `text-embedding-3-small` |
| `ai_transcribe_model` | select | `whisper-1` |
| `ai_monthly_budget_usd` | price | السقف الشهري للإنفاق |
| `ai_budget_alert_pct` | percentage | تنبيه عند بلوغ نسبة (مثلًا 80%) |
| `ai_rate_limit_per_min` | minutes/number | حد الطلبات/الدقيقة لكل مستخدم |
| `ai_phi_redaction` | boolean | إخفاء المعرّفات الشخصية قبل الإرسال |
| `ai_log_prompts` | boolean | هل نخزّن نص الـ prompt (للتدقيق) |
| `ai_patient_consent_required` | boolean | اشتراط موافقة المريض لمعالجة بياناته |

### 3.2 شاشات لوحة الأدمن (مجموعة سايدبار جديدة: «الذكاء الاصطناعي»)

| الصفحة | الوظيفة |
|---|---|
| `/admin/ai/settings` | المفتاح، النماذج، الميزانية، حدود المعدّل، الخصوصية + زر **اختبار الاتصال** |
| `/admin/ai/features` | تفعيل/تعطيل كل ميزة على حدة (feature flags) + اختيار نموذج لكل ميزة |
| `/admin/ai/prompts` | **قوالب الـ prompts** قابلة للتحرير (ar/en) لكل ميزة دون لمس الكود |
| `/admin/ai/usage` | لوحة استهلاك: تكلفة/توكنز شهريًا، حسب الميزة/المستخدم/الفرع + رسوم بيانية |
| `/admin/ai/logs` | سجل الطلبات (نجاح/فشل/زمن/تكلفة) + فلترة + تصدير |

> كل الصلاحيات عبر `config/permissions.php`: module جديد `ai` بأفعال
> `view, manage, prompts, logs`. أدوار super_admin/admin فقط افتراضيًا.

## 5. نموذج البيانات (جداول جديدة)

```sql
ai_request_logs       -- سجل كل نداء: feature, model, user_id, branch_id,
                      -- prompt_tokens, completion_tokens, cost_usd, latency_ms,
                      -- status, error, created_at  (للتدقيق + لوحة الاستهلاك)
ai_feature_flags      -- key, enabled, model_override, label_ar/en  (التحكم بكل ميزة)
ai_prompt_templates   -- feature, locale, system_prompt, user_template, version
                      -- (تحرير القوالب من اللوحة دون نشر كود)
ai_embeddings         -- owner_type, owner_id, vector(JSON), text  (للـ RAG: FAQ/خدمات)
ai_conversations      -- مساعد المريض: session, role, content  (سجل المحادثة)
```

> **قيد الاستضافة:** الخادم MySQL على cPanel مشترك (لا pgvector). الحل العملي: تخزين
> الـ embeddings كـ JSON وحساب التشابه (cosine) في PHP — كافٍ لأن مجموعة الأسئلة
> الشائعة/الخدمات صغيرة. لو كبرت لاحقًا → خدمة فيكتور مُدارة.

الإعدادات نفسها تبقى في `settings`/`module_settings` الموجودة (مع التشفير والفرع).

## 6. طبقة الأمان والامتثال (إلزامية)

- **تقليل/إخفاء PHI**: `PhiRedactor` يستبدل الاسم/الهاتف/الرقم القومي برموز قبل الإرسال،
  ويعيدها في العرض. مفعّل عبر `ai_phi_redaction`.
- **موافقة المريض**: عند `ai_patient_consent_required=true` لا تُعالَج بيانات مريض دون موافقة
  مسجّلة (نعيد استخدام جدول الموافقات الموجود).
- **لا قرار طبي تلقائي**: كل مخرَج سريري يحمل تنويه «مُولّد بالذكاء الاصطناعي — للمساعدة لا
  التشخيص» ويتطلب اعتماد الطبيب قبل الحفظ/الإرسال.
- **Moderation**: تمرير مدخلات المساعد العام على فلتر OpenAI moderation.
- **سياسة بيانات OpenAI**: استخدام الـ API (الافتراضي: لا تدريب على بياناتك) + توثيق ذلك.
- **تدقيق كامل**: كل طلب في `ai_request_logs` + ربطه بـ `medical_data_access_logs` عند مساس
  ببيانات مريض.
- **قاطع الميزانية**: عند بلوغ `ai_monthly_budget_usd` تتوقف النداءات تلقائيًا وتُنبّه الأدمن.
- **حد المعدّل** لكل مستخدم لمنع إساءة الاستخدام/التكلفة المفاجئة.

## 7. ضبط التكلفة (نموذج)

- **تدرّج النماذج**: `gpt-4o-mini` للمهام النصية الكثيرة (رسائل/ترجمة/SEO)، و`gpt-4o`
  للسريري/الرؤية فقط.
- **تخزين مؤقت**: ترجمات وأوصاف خدمات وembeddings تُحسب مرة وتُخزَّن.
- **عدّاد لكل طلب**: تكلفة تقديرية تُحسب من التوكنز وتُجمَّع شهريًا/فرع/ميزة.
- **سقف + تنبيه**: مثال — سقف 100$/شهر، تنبيه عند 80$.
- **Batch** للمهام غير الفورية (تلخيصات ليلية، توليد محتوى) لخفض التكلفة.

## 8. خارطة الطريق المرحلية

| المرحلة | المحتوى | الناتج |
|---|---|---|
| **0 — البنية التحتية** | AiManager + OpenAiDriver + NullDriver + Settings + ai_request_logs + شاشة `/admin/ai/settings` + Kill-switch + اختبار اتصال | أساس آمن قابل للتشغيل/الإيقاف |
| **1 — مكاسب سريعة** | الميزات 1–5 (SEO، صياغة رسائل، ترجمة، ردود Leads، حملات) | قيمة فورية بلا PHI |
| **2 — تفاعل المريض** | المساعد الذكي (RAG) + المشاعر + المتابعات + التذكيرات | تحويلات وولاء |
| **3 — مساعدة سريرية** | تلخيص الملف + ملاحظة SOAP + مساعد الوصفات + الخطط (إنسان في الحلقة) | كفاءة الأطباء |
| **4 — صوت/رؤية/تحليلات** | Whisper + رؤية الجلدية + تحليلات بلغة طبيعية + ملخص تنفيذي + OCR التأمين | تمييز تنافسي |
| **5 — تنبؤية** | توقّع الغياب + اقتراح المخزون | تحسين تشغيلي |

> كل مرحلة: migration (idempotent) → خدمة → شاشة/تفعيل → اختبارات → بناء ورفع.
> لا شيء يصل للإنتاج قبل `ai_enabled=true` + اختبار الاتصال.

## 9. المخاطر والتخفيف

| الخطر | التخفيف |
|---|---|
| تسرّب بيانات مرضى | PhiRedactor + موافقة + تدقيق + سياسة OpenAI |
| تكلفة منفلتة | سقف شهري + قاطع + تدرّج نماذج + تخزين مؤقت |
| اعتماد طبي خاطئ | تنويه + اعتماد بشري إلزامي + لا حفظ تلقائي |
| تعطّل المزوّد | NullDriver + بدائل + queue/retry |
| هلوسة المخرجات | قوالب prompt مضبوطة + RAG (مصادر حقيقية) + مراجعة بشرية |
| اللغة العربية | اختبار جودة المخرجات العربية + قوالب ثنائية |
