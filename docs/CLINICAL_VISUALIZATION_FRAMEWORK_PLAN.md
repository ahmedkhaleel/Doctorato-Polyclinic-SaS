# Clinical Visualization Framework
## إطار المؤشرات البصرية والشارتس السريرية لكل تخصص

**Date:** 2026-06-07 · **Type:** architecture + design-system + frontend plan
(تصميم + قرار معماري + خطة بناء — ليست تنفيذًا بعد)
**Scope:** doctor + admin panels · per visit + per patient file · every specialty
(present and future).

> الهدف: نظام **موحّد وقابل للتمديد** لعرض وتسجيل المؤشرات البصرية السريرية
> (odontogram، منحنيات النمو، اتجاهات المقاييس، خرائط الجسم…) — مبني مرّة، يُستفاد
> منه في كل تخصص، ويظهر في الزيارة وملف المريض للطبيب والأدمن، بتصميم احترافي وحركة
> راقية، **وأي تخصص جديد يحصل على هذه العناصر تلقائيًا** عبر التسجيل (registry).

---

## 1) الفحص — ما هو موجود فعلًا (grounded audit)

**لا توجد مكتبة شارتس** (`package.json` خالٍ من chart.js/apex/d3) — كل الرسوم **SVG يدوية
مكرّرة وغير متّسقة**. هذا هو جذر المشكلة.

| التخصص | العنصر البصري الموجود | الحالة | المعيار الدولي المتبقّي |
|---|---|---|---|
| 🦷 الأسنان | **Odontogram** كامل (DentalChart Show/Search + مصغّر في الزيارة) + أشعة | قوي | **مخطط لثة (periodontal pocket chart)** ناقص |
| 👶 الأطفال | **منحنيات WHO percentile** (وزن/طول/محيط رأس/BMI) — `PediatricGrowthChart` | قوي جدًا | **جدول تطعيمات بصري + معالم نمائية (milestones)** |
| 🩺 العلامات الحيوية | `VitalsHistorySection` اتجاهات (ضغط/حرارة/سكر…) | جيد | — |
| 🧠 نفسي/أعصاب | اتجاه المقاييس (sparkline + صفحة `/scales/{patient}/trend`) + MSE + Risk | جيد | **تقويم النوبات (seizure calendar) + يوميات الصداع + لوحة مزاج MBC** |
| 🌸 نساء/توليد | شريط عمر الحمل + تحاليل (بنيتها في لوحة الزيارة) | أساسي | **منحنى ارتفاع قاع الرحم + اتجاه ضغط/بروتين (تسمم حمل) + Partograph** |
| 💜 جلدية | Before/After slider + شريط تقدّم الجلسات | أساسي | **خريطة جسم للآفات (body lesion map) + مؤشر شدّة (PASI/EASI/SCORAD)** |
| عام | Admin `BarChart/DonutChart/MiniBarChart` (تقارير) | جيد | غير سريري |

**نقاط الربط الموجودة** (لا نخترعها): `Components/Patient/SpecialtyTabs.vue`
(تبويبات ملف المريض) · `Components/Doctor/Visit/SpecialtyPanel.vue` (لوحة الزيارة —
بُنيت حديثًا) · `Components/Clinical/*` (MseForm/RiskAssessmentPanel/ScaleRunner).

**الخلاصة:** القدرات السريرية الأساسية موجودة، لكن **لا طبقة بصرية مشتركة ولا registry**،
فكل تخصص يعيد الاختراع — والثلاثة الكبار (نساء/جلدية/أعصاب) ينقصهم عرض بصري بمعايير عالمية.

## 2) القرار المعماري — ADR: مكتبة شارتس أم SVG داخلي؟

### Option A — اعتماد مكتبة (Chart.js / ApexCharts / ECharts)
| البعد | التقييم |
|---|---|
| الحجم | +150–450 KB للحزمة (مشكلة على cPanel؛ الـ build مُلتزَم) |
| RTL/تعريب | متفاوت؛ يحتاج التفافات |
| الهوية/الحركة | تخصيص محدود، صعوبة مطابقة navy/gold + الحركة الحالية |
| السريري | الشارتس الطبية (odontogram، body-map، partograph) **ليست** charts عامة — المكتبة لا تغطّيها |

### ✅ Option B — **مجموعة SVG داخلية صغيرة (المُوصى به)**
طبقة `Components/Charts/` خفيفة (~10–15 KB إجمالًا)، تُبنى على نمط الـ SVG الموجود
(`PediatricGrowthChart`، الـ sparkline الجديد).
| البعد | التقييم |
|---|---|
| الحجم | ضئيل، لا تبعية خارجية |
| RTL/الهوية | تحكّم كامل (navy/gold، Tajawal، اتجاه) |
| الحركة | path draw-on + count-up + reduced-motion (البنية موجودة) |
| السريري | الأشكال الطبية المخصّصة (odontogram/body-map) أصلًا SVG يدوي — تتجانس |
| المخاطرة | منخفضة — لا تكسر شيئًا، تُعمّم ما هو مُثبت |

**القرار: Option B.** نبني **مجموعة بدائيات SVG مشتركة** + **registry**، ونعمّم الأنماط
المُثبتة (نمو الأطفال، اتجاه المقاييس). نلجأ لمكتبة فقط لو ظهرت حاجة تفاعلية معقّدة (zoom/pan)
مستقبلًا — معزولة خلف نفس الواجهة.

## 3) المعمارية — إطار التصوّر السريري (3 طبقات)

```
┌─ Layer 1 — Chart Primitives (Components/Charts/) — مشتركة، عامة ─────────┐
│  TrendLine · Sparkline · ReferenceBandChart (قيمة ضد المدى الطبيعي) ·     │
│  PercentileChart (مناطق مئوية) · ProgressRing · DonutGauge ·             │
│  CalendarHeatmap (نوبات/أعراض) · BodyMap (خريطة جسم) · StackedTimeline   │
│  → كلها: navy/gold، RTL، draw-on animation، reduced-motion، tooltip      │
└──────────────────────────────────────────────────────────────────────────┘
              ▲                         ▲                         ▲
┌─ Layer 2 — Clinical Indicator Registry (config-driven) ──────────────────┐
│  ClinicalVisualRegistry: module → [ { key, title, component, dataKey,    │
│  surfaces:[visit,file,admin], permission?, sensitive? } ]                 │
│  مثل ModuleManager للوحدات — تُعرّف مرّة، تظهر تلقائيًا في كل السطوح.       │
└──────────────────────────────────────────────────────────────────────────┘
              ▲                         ▲                         ▲
┌─ Layer 3 — Surfaces (نقاط العرض، موجودة) ────────────────────────────────┐
│  Visit page → SpecialtyPanel (يقرأ الـ registry)                          │
│  Patient file → SpecialtyTabs (يقرأ الـ registry)                         │
│  Admin → نفس المكوّنات بـ context="admin" (النمط المُثبت حديثًا)           │
└──────────────────────────────────────────────────────────────────────────┘
```

**جوهر «أي تخصص جديد يحصل عليها تلقائيًا»:** السطوح (Layer 3) لا تعرف التخصصات — تسأل
الـ registry: «ما العناصر البصرية لهذا الموديول؟» وتعرضها. إضافة تخصص = صفّ في الـ registry
+ مكوّن (غالبًا يعيد استخدام بدائية من Layer 1) + مصدر بيانات. **صفر تعديل في السطوح.**

### عقد الـ Backend
- `ClinicalVisualResolver::for($module, $patientId, $context)` يُرجع البيانات الجاهزة لكل
  مؤشّر مُسجَّل (يعيد استخدام النماذج القائمة: DentalChart، PediatricGrowthRecord،
  ScaleResult، ObgynLabTest، Vitals…).
- البيانات الحسّاسة (نفسي) تمرّ بنفس بوّابة `{module}.view_sensitive` + audit (مُثبتة).
- N+1-safe عبر علاقات المريض (نفس نمط لوحات الزيارة).

### الداتا بيز
- **الغالبية تُعاد استخدامها** (الجداول موجودة).
- جداول جديدة فقط للالتقاطات الجديدة: `derma_lesion_points` (خريطة الجسم)،
  `perio_measurements` (مخطط اللثة)، `obgyn_anc_measurements` (قاع الرحم/الضغط لكل زيارة)،
  وربما `neuro_event_log` (نوبات/صداع) إن لم يكن موجودًا. كلها migrations **idempotent +
  branch-aware + nullable→backfill** حسب قواعد المشروع.

## 5) نظام التصميم + الحركة (design-system + frontend)

- **بدائية موحّدة**: محور/شبكة خفيفة، نقاط تفاعلية، tooltip، وسم وحدات، شارة "خارج المدى".
- **مناطق مرجعية**: لكل مؤشّر **مدى طبيعي** مظلّل (مثل bands النمو) — القيمة خارجه تُلوّن أحمر.
- **الحركة**: رسم المسار تدريجيًا (stroke-dashoffset)، count-up للأرقام، ظهور متدرّج،
  **احترام `prefers-reduced-motion`** (البنية موجودة: `useCountUp`, قواعد app.css).
- **الهوية**: navy `#1B365D` + gold `#C4A265` + لون تخصّص للأكسنت، Tajawal/Poppins، **RTL أولًا**.
- **بلا إيموجي** — SVG فقط (يحرسه `NoEmojiInPagesTest`)، وكل أيقونة زر لها aria-label.

## 6) UX copy (ux-copy)
- وحدات صريحة بجانب كل قيمة (mmHg, kg, g/dL, weeks).
- لغة المدى المرجعي: «طبيعي / مرتفع / منخفض» (ar) — «Normal / High / Low» (en)، لا اختصارات غامضة.
- حالات فارغة سريرية بـ `UiEmptyState` + CTA «سجّل أول قياس».
- نص حسّاس للنفسي: «محجوب — يتطلب صلاحية البيانات الحسّاسة».

## 8) الاختبار والسلامة (لا شيء يُكسر — front/back/db)

- **CV-0/CV-1 شبكة أمان**: إعادة توصيل العناصر الموجودة بسلوك **مطابق** قبل أي ميزة جديدة؛
  اختبار عقد لكل resolver (مثل اختبارات لوحات الزيارة).
- **حُرّاس الواجهة** (Emoji/IconLabel/ImageAlt/FocusTrap/Title) يجب أن تبقى خضراء.
- **Migrations**: idempotent + `branch_id` nullable + backfill→1 + فهرس مركّب؛ تشغيل على
  staging قبل الإنتاج.
- **manifest**: كل صفحة Vue جديدة → `npm run build` + commit (يفحصها CI).
- **المجموعة الكاملة** (`composer test`) خضراء بعد كل مرحلة + نشر متحقّق (CI + Deploy + /health).
- **الحساسية**: لا تسريب بيانات نفسية — نفس البوّابة + audit.
- **الأداء**: الشارتس SVG خفيفة؛ lazy-load للمكوّنات الثقيلة (body-map) كما في لوحات الزيارة.

## 10) ملخّص القرار

> الأساس قوي (odontogram + WHO growth + scale/vitals trends)، لكن **مبعثر بلا طبقة مشتركة
> ولا registry**، والثلاثة الكبار (نساء/جلدية/أعصاب) ينقصهم عرض بصري عالمي. الخطة تبني
> **مجموعة بدائيات SVG + registry موجَّه بالإعداد** فتُعمَّم العناصر المُثبتة، وتُضاف الناقصة
> بمعايير دولية، وتظهر موحّدة في الزيارة + ملف المريض للطبيب والأدمن — على مراحل، كلٌّ
> باختبار ونشر متحقّق، **وأي تخصص جديد يرث هذه العناصر تلقائيًا**.
